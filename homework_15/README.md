# ДЗ15 (Заняття 30) — Постинг результатів на сервер курсу

HTTP-клієнт, який надсилає результати прогонів симулятора (`simulation.json`)
на сервер курсу і перевіряє, що вони там опинилися.

Мережевий код власний — **cpp-httplib** (header-only). Зовнішні програми
(`curl` тощо) не викликаються, як вимагає ТЗ.

## Структура

```
homework_15/
├── CMakeLists.txt
├── include/
│   ├── UploadTypes.h        типи статусів і рядок звіту
│   ├── ResultUploader.h     інтерфейс клієнта
│   ├── httplib.h            cpp-httplib 0.51.0
│   └── json.hpp             nlohmann/json 3.12.0
├── src/
│   ├── main.cpp             розбір аргументів, запуск
│   └── ResultUploader.cpp   POST + ретраї + контрольний GET
└── tools/
    └── mock_server.py       локальний макет сервера для налагодження
```

## Підключення до збірки

У кореневий `CMakeLists.txt` додати:

```cmake
add_subdirectory(homework_15)
```

Збірка:

```bash
cmake --preset debug
cmake --build --preset debug
```

## Підготовка даних

Клієнт читає `results/<TestId>/simulation.json`. Розкладіть результати прогонів:

```bash
mkdir -p results/T01
cp build/debug/homework_08/simulation.json results/T01/simulation.json
```

Відсутні тести не є помилкою — ТЗ дозволяє надсилати ті, що є; решта потрапить
у звіт зі статусом «ПРОПУЩЕНО».

## Запуск

```bash
./homework_15 --student <ВАШ_ID>
```

| Опція | Призначення | Типово |
|---|---|---|
| `--student <ID>` | ваш studentId (**обов'язково**) | — |
| `--results <dir>` | каталог з результатами | `results` |
| `--host <host>` | хост сервера | `cppmiltech.com.ua` |
| `--port <n>` | порт | `80` |
| `--key <key>` | значення `x-api-key` | ключ курсу |
| `--tests <list>` | список тестів через кому | `T01…T10` |
| `--quiet` | без покрокового логу | вимкнено |

Код повернення: `0` — усе успішно (відсутні файли не рахуються за помилку),
`2` — хоча б один тест провалився з мережевої чи протокольної причини.

## Як виконано вимоги ТЗ

| Пункт | Реалізація |
|---|---|
| 1. POST для кожного теста | `ResultUploader::uploadAll()`; тіло — `{studentId, testId, simulation}` |
| 2. Таймаути ≤ 2 с | `set_connection_timeout(2,0)`, `set_read_timeout(2,0)` |
| 3. Розрізнення кодів | `ResultUploader::classify()` → `Done` / `Stop` / `Again` |
| 4. ≤ 5 спроб, пауза ≥ 1 с | цикл `for` з `maxAttempts`, `sleep_for(1000 мс)`; невдача → запис у звіт, перехід далі |
| 5. Контрольний GET | `verifyOnServer()`, перевіряє `found:true` у тілі 200 |
| 6. Ідемпотентність | локальний стан між запусками не зберігається; повтор дає 200 замість 201 |
| 7. Звіт | `printReport()`: тест → статус → спроби → підтвердження GET |

Рішення «повторювати чи ні» винесено в окремий `enum class RetryDecision`,
щоб логіка була явною, а не схованою в ланцюжку `if`-ів.

## Налагодження без справжнього сервера

`tools/mock_server.py` відтворює протокол разом зі сценаріями, які на живому
сервері на замовлення не викличеш:

| Тест | Поведінка макета | Що перевіряє |
|---|---|---|
| T01 | 201, при повторі 200 | нормальний шлях + ідемпотентність |
| T02 | 400 | повтору **не** має бути |
| T03 | 401 | повтору **не** має бути |
| T04 | 503 двічі, далі 201 | ретрай дотискає результат |
| T05 | 503 завжди | вичерпання 5 спроб |
| T06 | тиша 10 с | спрацювання таймауту читання |

```bash
python3 tools/mock_server.py 8080          # у першому терміналі
./homework_15 --student 2042 --host 127.0.0.1 --port 8080   # у другому
```

Перевірені заміри: T05 — 4.02 с (4 паузи по 1 с), T06 — 14.02 с
(5 × 2 с таймаут + 4 × 1 с пауза). Обидва відповідають ТЗ.
