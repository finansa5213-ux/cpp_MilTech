# homework_17 — ДЗ Заняття 34: телеметрія дрона по MAVLink 2 / UDP

Симулятор дрона шле телеметрію MAVLink 2 по UDP і виконує скид вантажу
командою `MAV_CMD_USER_1` з підтвердженням (`COMMAND_ACK`) та повторами.

Жодного заліза не потрібно: все працює через loopback на одній машині.

## Структура

```
include/
  transport.hpp      інтерфейс каналу байтів (дозволяє тестувати без сокета)
  udp_socket.hpp     неблокуючий UDP поверх ITransport
  geo.hpp            локальні метри -> градуси, робота з курсом
  mavlink_link.hpp   пакування кадрів MAVLink 2 + FSM повторів команди скиду
  drone_sim.hpp      ДОВІДКОВА модель польоту (замінюється кодом ДЗ11)
src/                 реалізації + main.cpp (реал-тайм цикл)
tests/               GoogleTest: геометрія, одиниці полів, повтори до ACK
tools/fake_checker.py  локальний «псевдочекер» для самоперевірки
```

Ключова ідея архітектури: `MavlinkLink` нічого не знає про фізику. Він приймає
готову структуру `TelemetrySample`. Тому підключення власного симулятора з ДЗ11
зводиться до заповнення цієї структури з вашого стану.

## Підключення до репозиторію

У кореневому `CMakeLists.txt` додати рядок поруч з іншими ДЗ:

```cmake

```


з логікою), `homework_17_tests` (GoogleTest).

## Запуск


## QGroundControl

Запустіть QGC і симулятор — дрон з'явиться на мапі автоматично (QGC слухає
UDP :14550). QGC **не** відповідає ACK на `MAV_CMD_USER_1` — це очікувано:
програма чесно робить 5 спроб, друкує «ACK не отримано», телеметрія не зупиняється.

Чекер і QGC одночасно не піднімуться — обидва займають порт 14550.

### Нюанс WSL2 + QGC на Windows

Якщо симулятор у WSL2, а QGroundControl встановлений у Windows, `127.0.0.1`
до нього не долетить: у WSL2 власний мережевий стек. Два варіанти:

**1. Дзеркальна мережа** (простіше). У `C:\Users\<user>\.wslconfig`:

```ini
[wsl2]
networkingMode=mirrored
```

Далі `wsl --shutdown`. Після цього дефолтні параметри працюють без змін.

**2. Явна адреса хоста:**

```bash
./build/homework_17/drone --dest $(ip route show default | awk '{print $3}'):14550
```

У Windows Firewall потрібно дозволити вхідний UDP 14550 для QGroundControl.

Чекер цього не стосується: його запускають усередині WSL2, і там `127.0.0.1`
працює як звичайно.

## Чекер курсу

Порт передається першим позиційним аргументом:

```bash
chmod +x checker-linux-x86_64
./checker-linux-x86_64 14550      # ЗАМІСТЬ QGC, на тому самому порту
./build/homework_17/drone         # у другому терміналі
```

Перший `COMMAND_LONG` чекер ігнорує навмисно, ACK надсилає на другу спробу.
Звіт друкується після того, як дрон припинить слати телеметрію.

## Локальна самоперевірка без чекера

```bash
python3 tools/fake_checker.py --ack-on 2 &   # ACK на другу спробу
./build/homework_17/drone
```

`--ack-on 0` — ACK не надходить ніколи (перевірка рівно 5 спроб).

## Відповідність вимогам ДЗ

| Вимога | Де реалізовано |
|---|---|
| MAVLink 2, стабільні sysid/compid | `MavlinkLink` (конструктор знімає `OUT_MAVLINK1`), sysid=1, compid=`MAV_COMP_ID_AUTOPILOT1` |
| HEARTBEAT ~1 Гц, QUADROTOR/ACTIVE | `sendHeartbeat()`, `kHeartbeatPeriodS` у `main.cpp` |
| Телеметрія ≥2 Гц | `kTelemetryPeriodS = 0.1` (10 Гц) |
| `time_boot_ms` монотонний | час симуляції від старту в мс |
| lat/lon ×1e7, alt мм, vx/vy см/с, hdg сот. градуса | `degTo1e7`, `metersToMm`, `mpsToCms`, `headingToCentiDeg` |
| hdg відповідає напрямку руху | `headingFromVelocityDeg()`, той самий кут у `ATTITUDE.yaw` |
| COMMAND_LONG з координатами скиду | `requestDrop()` / `sendDropCommand()`; `param5/6` — позиція дрона в момент випуску (чекер вимагає ≤500 м від поточної позиції), `param7` — висота в метрах |
| Повтор до ACK, до 5 спроб, таймаут | `MavlinkLink::poll()`, `kMaxDropAttempts=5`, `kAckTimeoutMs=500` |
| Після ACK — тиша | `DropState::Acked` блокує повтори |
| Телеметрія не зупиняється під час повторів | повтори неблокуючі, живуть у `poll()` головного циклу |
